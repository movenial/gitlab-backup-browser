Open source · MIT · one static binary

Your GitLab backup, browsable without restoring it.

Point gbb at a *_gitlab_backup.tar and get a read-only, GitLab-like web UI plus git clone URLs, on a laptop, a NAS, a Raspberry Pi or an old Android phone. No GitLab, no PostgreSQL, no Redis, no Docker.

Why

Restoring a GitLab backup means standing up a GitLab of the exact same version first.

Then restoring everything into it. That is heavy when all you need is the code, the issues, or the certainty that the backup is good.

  • During an outage

    GitLab is down. Serve the last backup from any machine and keep cloning and reading.

  • After decommissioning

    The instance is gone, the tarball stays. Open it years later without rebuilding the exact GitLab it came from.

  • Every night

    A backup nobody has opened is a hope, not a backup. gbb verify checks it after each run.

Verify

Know whether last night's backup is complete.

The same binary reads the backup, compares it with the previous one and tells you what changed: deleted projects, fewer issues, moved or deleted tags and branches. With --deep it also tells rewound and force-pushed branches from normal pushes, restores every repository and checks every object, LFS file and attachment.

0ok
1warnings, e.g. something disappeared since the previous backup
2errors: unreadable dump, missing bundles, missing files

What you get

Most of what you open GitLab for, read-only.

Repositories are read in place: an uncompressed .tar is never extracted. gbb is up in seconds and unbundles a repository the first time you open it.

Code

  • File tree, syntax highlighting for about 25 languages, rendered Markdown, images
  • Branches, tags, history (per file too), commits with diffs, compare any two refs
  • Links to a line or a range of lines, with a link that pins the commit
  • Code search across the default branch of every project, text or regex, streamed
  • Raw files and .zip downloads of any branch, tag or commit

Git

  • git clone and fetch of every repository and wiki, with any git client
  • Git LFS files, shown in the browser and fetched by git clone
  • Snippets, project and personal, browsable and clonable
  • Projects without a repository and orphan bundles are shown: nothing in the backup is hidden

Issues and merge requests

  • Issues and merge requests with comments, attachments, labels (scoped too) and milestones
  • Each merge request's changes, with highlighted diffs
  • Releases with their notes and asset links, served from the backup
  • Groups, subgroups and users with real names, descriptions, visibility and archived state

Operations

  • A Backups page to switch between the archives in a directory
  • Extract LFS or uploads, pre-unbundle the busiest repositories, delete old caches
  • Optional login (--auth); the maintenance buttons stay off on the network without it
  • Every repository is clonable, so a few lines of shell export them all to a folder, Forgejo or Gitea

Runs anywhere

On whatever hardware is left standing.

  • One static binaryPure Go, no cgo, no runtime to install. The only dependency is goldmark, for Markdown.
  • Small and steady memoryPack indexes are memory-mapped and idle repositories are closed. The soft limit is 128 MiB on Android, 256 MiB elsewhere.
  • Tested on real backupsEnd to end on generated backups and on a real GitLab 19.5.3 backup of 28.8 GB with 657 projects. Reports from other GitLab versions are welcome.

Install

Download, check, run.

Every release ships a SHA256SUMS to check the binaries against.

Release binary

Pick yours from the latest release; Linux amd64 shown here.

curl -fLO https://github.com/movenial/gitlab-backup-browser/releases/latest/download/gbb-linux-amd64
curl -fLO https://github.com/movenial/gitlab-backup-browser/releases/latest/download/SHA256SUMS
sha256sum -c --ignore-missing SHA256SUMS
sudo install -m 755 gbb-linux-amd64 /usr/local/bin/gbb

With Go

go install github.com/movenial/gitlab-backup-browser/cmd/gbb@latest

Nightly check from cron, with Docker

The image holds only the linux-amd64 binary. Replace <tag> with a release tag.

docker run --rm -v /var/opt/gitlab/backups:/backups:ro -v gbb-data:/data \
  ghcr.io/movenial/gitlab-backup-browser:<tag> verify --data /data /backups/<backup>.tar

How it works

No PostgreSQL, no restore: the backup is read as it is.

backup.tar ──┬── db/database.sql.gz ──► streaming COPY parser ──► index.json
             │                            (no PostgreSQL)          + issues on disk
             │
             └── repositories/**/*.bundle ──► on first visit: pack + .idx ──► web UI
                    (read in place)              (pure Go, like git           + git clone
                                                  index-pack --fix-thin)        (smart HTTP)
  1. Scan. Tar headers are read and bodies skipped by seeking, so repositories appear within seconds.
  2. Database. The dump is decompressed as a stream; only the tables gbb shows are decoded. Tokens, secrets and password hashes are skipped without being parsed.
  3. Index. Hashed storage paths are joined with project paths and saved as a small index, reused until the backup changes.
  4. Clone. Repositories are served over git's smart HTTP protocol, sending the packs as they are on disk: nothing is recompressed.

Not yet supported

What gbb does not do.

  • Group wikis, design management files, epics. Group wikis are skipped; design files are checked by verify but not browsable.
  • CI/CD data, packages, container images. Out of scope for a lightweight browser.
  • Backups on S3 or MinIO. Read a local file or directory for now.
  • Shallow and partial clones, SHA-256 repositories. Fetches always download the whole repository.
  • Several users or per-project permissions. One login sees everything.
  • Search across all issues and merge requests. Search is per project.
